What is online softmax, and how is it different from normal softmax?

Deep Learning · softmax · FlashAttention · numerical stability · GPU kernels

1Definition

Softmax turns a vector of scores (logits) into a probability distribution: each element becomes exp(xᵢ − m) / Σⱼ exp(xⱼ − m), where subtracting the maximum m prevents overflow ("safe softmax"). Computed the normal way this needs three passes over the data: one to find the max, one to sum the exponentials, one to normalize — so the whole vector must be available (materialized in memory) before you can start.

Online softmax produces the exact same result in a single streaming pass. It maintains just two running scalars — the max m and the denominator d — and when a new element beats the current max, it rescales the accumulated denominator by exp(m_old − m_new) instead of starting over. The difference is purely computational, not mathematical: same output, but O(1) extra memory, one pass, and no need to ever hold the full vector — which is what lets FlashAttention compute attention without materializing the n×n score matrix.

2Analogy

You're judging auditions that arrive one at a time, and to keep numbers manageable you score everyone relative to the best act so far. You keep two sticky notes: "best so far" and a running total of relative scores. When contestant #7 blows the current champion away, you don't call back contestants 1–6 to re-judge them (that's normal softmax's extra pass). Instead you do one currency conversion: your whole running total was measured in "old-champion units," so you multiply it once by the exchange rate exp(old best − new best) and carry on. When the last act finishes, your total is exactly what a judge who had seen everyone up front would have computed — but you only ever needed two sticky notes, no matter how long the line was.

4History → Current → Future

1868–1902
The functional form is the Boltzmann/Gibbs distribution from statistical mechanics; "softmax" as a neural-network output layer is popularized by John Bridle in 1989, and max-subtraction becomes the standard numerical-stability trick.
2018
Milakov & Gimelshein (NVIDIA) publish "Online normalizer calculation for softmax" — the one-pass recurrence with max-rescaling, motivated by cutting memory traffic in GPU kernels.
2022
FlashAttention (Tri Dao et al.) combines online softmax with tiling: attention is computed block by block in fast on-chip SRAM, rescaling partial results as new blocks arrive, so the n×n attention matrix is never written to slow GPU memory — exact attention, 2–4× faster, O(n) memory.
Current
Every serious LLM stack uses it: FlashAttention-2/3 (better parallelism, Hopper-specific speedups), and the same merge rule powers Ring Attention (streaming blocks across GPUs for million-token contexts) and paged/chunked inference kernels.
Future
The pattern — "stream blocks, keep running statistics, rescale on the fly" — is becoming a general recipe for low-precision (FP8/FP4) and hardware-aware kernels, and for any normalizer computed over data too big to hold at once.

5Example

Stream the logits [2, 1, 5, 3] one at a time, keeping max m and denominator d:

  • x=2: first element → m = 2, d = e⁰ = 1
  • x=1: no new max → d = 1 + e^(1−2) = 1 + 0.368 = 1.368
  • x=5: new max! rescale: d = 1.368 · e^(2−5) + e⁰ = 0.068 + 1 = 1.068, m = 5
  • x=3: no new max → d = 1.068 + e^(3−5) = 1.068 + 0.135 = 1.203

Final probabilities: e^(xᵢ−5) / 1.203 → [0.041, 0.015, 0.831, 0.112]. Normal softmax on the full vector gives exactly the same numbers — but it first scanned all four values to find m = 5, then made a second pass to build the sum. The online version never looked back: one rescale multiply replaced a whole extra pass.

6Use cases

  • FlashAttention: the flagship use — computing softmax(QKᵀ)V tile by tile in on-chip SRAM, making exact long-context attention memory-linear instead of quadratic.
  • Ring / distributed attention: each GPU computes attention over its shard of a million-token context; the per-shard (m, d, partial output) triples are merged with the same rescaling rule.
  • Chunked-prefill & paged inference kernels (vLLM-style): scores over the KV cache are processed in pages that never coexist in fast memory.
  • Huge output vocabularies: streaming log-sum-exp over millions of classes (extreme classification, retrieval scoring) without materializing all logits.
  • Hardware accelerators: softmax units with tiny local buffers compute exact results over long vectors in one pass.
  • Any streaming normalizer: numerically stable log-sum-exp over data arriving from disk or network, e.g. in probabilistic programming.

7Math & Python

Normal (safe, three-pass) softmax:

m = maxj xj,   d = Σj exj−m,   softmax(x)i = exi−m / d

Online softmax replaces the two reduction passes with one recurrence. With m₀ = −∞, d₀ = 0, for each incoming xᵢ:

mi = max(mi−1, xi),   di = di−1 · emi−1−mi + exi−mi

The rescale factor e^(mᵢ₋₁−mᵢ) is 1 when the max doesn't change and shrinks the old sum exactly when it does — an inductive proof shows (mN, dN) always equal the three-pass values. The same trick merges two independently processed blocks, which is the FlashAttention composition rule:

import numpy as np

def softmax_normal(x):
    """Safe softmax: needs the whole vector, three passes."""
    m = np.max(x)                    # pass 1: find max
    e = np.exp(x - m)                # pass 2: exponentiate & sum
    return e / e.sum()               # pass 3: normalize

def softmax_online(stream):
    """One pass, O(1) state — works on any iterable, even one you can't rewind."""
    m, d, seen = -np.inf, 0.0, []
    for x in stream:
        m_new = max(m, x)
        d = d * np.exp(m - m_new) + np.exp(x - m_new)   # rescale + accumulate
        m, _ = m_new, seen.append(x)
    return np.exp(np.array(seen) - m) / d

def merge_blocks(m1, d1, m2, d2):
    """FlashAttention's rule: combine stats of two blocks processed separately."""
    m = max(m1, m2)
    return m, d1 * np.exp(m1 - m) + d2 * np.exp(m2 - m)

x = np.random.randn(1000) * 5
assert np.allclose(softmax_normal(x), softmax_online(x))   # identical results

# Blockwise == full-vector: the property FlashAttention is built on
mA, dA = x[:500].max(), np.exp(x[:500] - x[:500].max()).sum()
mB, dB = x[500:].max(), np.exp(x[500:] - x[500:].max()).sum()
m, d = merge_blocks(mA, dA, mB, dB)
assert np.isclose(d, np.exp(x - m).sum())
print("online == normal, blocks merge exactly ✓")
